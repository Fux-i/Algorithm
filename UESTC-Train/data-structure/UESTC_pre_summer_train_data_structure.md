## B. 树上数颜色

看这题第一眼想法就是树形 DP，开个`[node][color]`的二维数组，递归统计以`node`为根的子树的所有颜色数量，
虽然时间空间都超了，但也没有其他思路了，只能先硬着头皮试一试，结果不出意外 MLE 了。

好吧，只能去学一下能高效做子树查询的数据结构了，也就是 dsu on tree 的这么个东西。
相比之前的朴素解法，该算法的高明之处在于：

1. 用单个全局变量`cnt[maxn]`（$O(n)$）来保存所有颜色数量，而不用维护 $O(n^2)$ 的二维数组
2. 为了避免试用全局变量时不同子树互相干扰的问题，区分重儿子和轻儿子，先遍历所有轻儿子取得结果后清除对`cnt[maxn]`的影响，
   把重儿子留到最后，保留影响。这样每个节点就最多被计算 $O(\log n)$ 次，因此时间复杂度可以降到 $O(nlogn)$

回到代码，首先是基础的数据读入，这里用链式前向星来存树，由于是有根树，就不用当做无向边存两遍了。

其中 dfs1 是用来找重儿子的，dfs2 才是真正开始计算，因为需要 dfs1 结束后才知道谁是重儿子，才知道以什么顺序来计算。
这里需要注意处理重儿子时要保留影响，参数`clear`为`false`

add 函数也要注意，递归累计颜色数量时要调过重儿子，但清除时不能跳过，否则会影响`node`同级的其他子树。

## D. 线段树全家桶

额额很好的线段树全家桶，线段树是一种可以在 $O(\log n)$ 时间复杂度内实现区间修改、查询操作的高效数据结构。
本质上是二叉树，每个叶子节点对应数组中的单个值，非叶子节点则对应$[l, r]$区间中的信息（区间和、最大值等），一开始我疑惑这里的`l`和`r`是怎么来的呢？
多用了几次才领悟到这就是线段树的精髓所在，`l`和`r`不会直接给出，而是**必须**每次查询/修改时一路递归演变下来，顺带把该计算的都计算了，
不需要存在节点中。

在做实现区间修改时，为了避免递归到叶子节点，可以用到懒标记，等查询到这个节点时，再做更新。我的代码中线段树节点定义如下：

```c++
 struct Node {
     ll val = 0;    // 区间和
     ll max = 0;    // 区间最大值
     ll mul = 1;
     ll add = 0;
 };
```

这里用`mul`和`add`两个值来作为懒标记，处理逻辑需要仔细琢磨，尤其是处理`val`和`add`本身时，要考虑区间覆盖的范围，加`add * (r - l + 1)`

`apply`实现如下：

```c++
 void apply(ll idx, ll l, ll r, ll mul, ll add) {
     Node &o = tree[idx];
     o = {
         o.val * mul + add * (r - l + 1),
         o.max * mul + add,
         o.mul * mul,
         o.add * mul + add
     };
 }
```

所以 range assign 时只需`tree[idx] = {ass * (r - l + 1), ass, 0, ass};`就好了，assign 会直接覆盖原有的未处理的`mul`和`add`。

## G. 河符（Dividing Edge）

每次删除一些边，求联通块数量，暴力算法时间复杂度为 $O(k·m) \approx 2 \times 10^8$ 显然会超时，需要更高效的做法。

观察到 $n$ 的范围比较小，且总编号范围会被“烧掉的电线编号范围”分为前后两份，那可以维护以 $i$ 为索引的前缀并查集和后缀并查集，
每次查询时，合并前后两部分再统计联通块数即可把查询时间复杂度降到 $O(k·n)$

## I. 菜猫充电器

三维偏序，经典 CDQ 分治，大致流程描述如下：

1. 按 `a` -> `b` -> `c` 排序
2. 递归处理前后两部分
3. 按 `b` 排序这两部分
4. 前半部分 `++i`，后半部分 `++j`，用树状数组累计 $c_i$ <= $c_j$ 的数量
5. 清除对树状数组的修改，以免影响其他区间的累计

可以提前对所有充电器去重，来优化后续计算，注意后续要累计 `cnt`

这样处理后看时间复杂度，预先全量排序为 $O(n\log n)$，去重 $O(n)$；

CDQ 中递归 $O(\log n)$，排序 $O(n\log n)$，树状数组累计 `res` $O(n\log n)$，总计 CDQ $O(n\log^2 n)$；

于是总体时间复杂度 $O(n\log^2 n)$，在给定数据规模下可以通过

## J. 菜猫的大手

求是否有连续区间长 $j$，区间内每个元素都 $\ge b_j$
$=>$ 对于所有长为 $j$ 的区间，是否存在某个区间的最小值 $\ge b_j$
$=>$ 对于所有长为 $j$ 的区间，它们的最小值中，最大的那个是否 $\ge b_j$

所以可以分别正向和反向遍历一次，用栈来得到最近的小于 $a_i$ 的左右两个数，也就求出了最小值为 $a_i$ 的区间 left_bound(lb) 与 right_bound(rb)
$=>$ 求出最小值为 $a_i$ 的区间长度
$=>$ 遍历区间长度求出同一长度区间的最小值中的最大值 $best[len]$

当然，由于 $len$ 可能没有覆盖完所有可能值，所以需要再倒序遍历一次 `best[i] = max(best[i], best[i + 1]);`，

所有操作都是 $O(n)$ 的时间复杂度，总体时间复杂度也是 $O(n)$

## L. 重生之我是ICPC冠军

由于总罚时为所有题目的**完成时刻之和**，显然最先完成的题目对总罚时的影响最大，所以为了总罚时最小，应该优先完成 $c_i$ 最小的题目。
再考虑到参赛三人有不同的特定离开时间，所以还应尽量保证最先离开的队员适合的题目先被完成。

那么解法也就比较明晰了：

1. 将参赛三人按离开时间升序排序为 0、1、2
2. 用小顶堆维护所有待解决的题目，每次先尝试处理耗时最短的题目
3. 若待处理题目适合的人就是排序最靠前的队员，则可直接完成，否则需判断先完成此题会不会使得前面的队员在离开之前无法完成所有适合的题目

在实际写代码的时候，发现坑还不少，尤其是对参赛三人排序后如何处理，因为`idx[i]`没用/用错导致卡了许久；
暂时不完成的题目应先放入暂存区中，待当前参赛队员的题目全部完成后，重新加入堆。

此外，还可以在对参赛三人排序后快速预检一遍，若“优先完成下一个离开的队员适合的题目”都超时了，则直接输出 `NO`。

总体时间复杂度 $O(n\log n)$

## M. 这是一道算一血的简单题

求满足最大值与最小值之差大于`k`的区间数量，显然，若某一区间满足条件，则任何包括该区间在内的所有区间都满足条件。

用滑动窗口的思想来解决，先固定`l`，找到一个满足条件的最小区间`[l, r]`，`l`表示区间左端点，`r`表示区间右端点的最小指，
则以`l`为左端点的满足条件的区间数量为`n - r`，随后挪动`l`重复运算累积即可。

为了维护区间内的最大值和最小值，可以用`deque`按条件存储下标，队头始终表示最大/小值的下标，挪动`l`时判断其是否仍在区间内。

## P. 雪堆

本题数据规模为$1e5$，那应该是要想个 $O(n\log n)$ 的算法，第一反应就是二分查找，或线段树，但本题用线段树有点大材小用了。

先假设所有雪堆都是无限大，那么每天融化的体积就是$t_i \times n_i$（$n_i$为第$i$天剩余雪堆数），考虑有限大的雪堆，那就是
$t_i \times n_i + x$（$x$为恰好在第$i$天融化完的雪堆的当天融化体积之和）。

现在进入关键点了：如何 $O(n\log n)$ 的时间复杂度内求出每个雪堆融化完的时间？这里我用的是前缀和+二分查找：

`sum_t[i]`表示`t[0] + t[1] + ... + t[i - 1]`，`last`表示`i`为`last[i].first`个雪堆存活的最后一天，
这些雪堆最后一天共融化的体积为`last[i].second`。注意，由于每个雪堆的起始时间不同，需要加上`sum_t[i]`来复用`sum_t`做二分查找。

```c++
 vector<ll> v(n), t(n), sum_t(n + 1);
 vector<pll> last(n);
 for (ll i = 0; i < n; ++i) {
     ll temp_v = v[i] + sum_t[i];
     ll d = ranges::lower_bound(sum_t.begin() + i + 1, sum_t.end(), temp_v) - sum_t.begin() - 1;
     if (d == n) continue;
     last[d].first++;
     last[d].second += temp_v - sum_t[d];
 }
```

最后的计算如下：

```c++
 ll num_alive = 0;
 for (ll i = 0; i < n; ++i) {
     num_alive++;
     num_alive -= last[i].first;
     cout << num_alive * t[i] + last[i].second << " \n"[i == n - 1];
 }
```

## Y. 我的思路无懈可击

修改子树 + 修改节点到根路径上的节点 + 单点查询，在 $5 \times 10^5$ 的规模下可以用树链剖分 + 线段树。

树链剖分使得重链上节点的 dfs 序连续，且用 `fa` 记录了所有节点的父节点方便向上跳到根，这样两种修改操作都能转化为线段树的区间赋值：

- 操作 1（装满水）就是 `update(dfn[u], dfn[u]+siz[u]-1, 1)`，时间复杂度 $O(\log n)$
- 操作 2（排尽水）则沿重链往上跳，每段 `update(dfn[top[u]], dfn[u], 0)`，跳到根为止，时间复杂度 $O(\log^2 n)$
